# Artifact Contract

Write these artifacts under the run output directory (`--out-dir`).

## Run directory layout

```
<out-dir>/
├── run-summary.json              # orchestrate-e2e JSON artifact (gates, level, approach, evidence, ml_test_score)
├── evidence.md                   # all gates: showboat evidence notebook (commands + real outputs, re-runnable)
├── evidence-verify.txt           # gate 10: output of `showboat verify`
├── select-approach.json          # gate 0: approach selection and lifecycle map
├── review-target.json            # gate 1: target readiness
├── splits/                       # gate 1: split_assignments.csv + split-manifest.json (test set locked)
├── check-dataset-quality.json    # gate 2: dataset audit
├── data-contract.json            # gate 2: schema expectations for training and serving
├── training-profile.json         # gate 2: drift baseline from the train split
├── build-baseline.json           # gate 3: baselines (fit on train, scored on val)
├── predictions/                  # baseline_*_val.csv, model_val.csv, model_test.csv (final only)
├── plan-experiment.json          # gate 4: experiment plan
├── feature-engineer.json         # gate 4b: feature contract (optional; when data is raw)
├── check-data-pipeline.json      # gate 5: pipeline validation
├── train-model.json              # gate 6: training run summary
├── provenance-train.json         # gate 6: git, environment, data hashes, seed
├── model.joblib                  # gate 6: fitted pipeline from train_tabular.py (or a checkpoint dir)
├── train-config.json             # gate 6: features, params, seed, data and test-key hashes
├── train-metrics.json            # gate 6: validation and CV metrics, best iteration
├── model/                        # gate 9: packaged model and signature.json
├── babysit-training.json         # gate 6 (sub): training monitoring (written by train-model)
├── check-failed-run.json         # gate 6 (sub): failure diagnosis (when invoked by train-model)
├── check-eval.json               # gates 7 and 10: validation results, then the final test evaluation
├── eval-metrics-val.json         # gate 7: eval_report.py output (intervals, slices, calibration)
├── eval-metrics-test.json        # gate 10: final test evaluation (once)
├── explain-model.json            # gate 8: explainability and bias audit
├── check-deployment-readiness.json # gate 9: parity, latency, contract, plans
├── serving-check.json            # gate 9: serving_check.py output
├── monitoring-plan.md            # gate 9: monitoring, rollout, and rollback plan
├── demonstrate-value.json        # optional: business value presentation metadata
├── value-demo.html               # optional: stakeholder presentation (generated by demonstrate-value)
├── build-review-page.json        # review pages built, their check results, pages omitted
├── review/                       # one-minute review pages (decision.html, label.html, ...) and responses.jsonl
├── value_calc.py                 # optional: business-impact calculation (recorded in evidence.md)
├── recommend-new-approaches.json # informational: ranked next experiments
├── report.html                   # generated viewer (from generate_report.py)
├── run-contract.md               # objective, label, metric, threshold, budget
├── gate-status.md                # gate status table with PASS/FAIL/SKIPPED
├── run-timeline.md               # chronological action log
├── evaluation-summary.md         # metric table and baseline deltas
└── decision.md                   # final GO/NO-GO with blockers, sign-off, and next commands
```

## Required markdown files

1. `run-contract.md`
   - Objective, label, metric, threshold, budget, retry policy, promotion criteria

2. `gate-status.md`
   - One row per lifecycle gate with status (`PASS`, `FAIL`, `SKIPPED`)
   - Evidence path(s) and timestamp

3. `run-timeline.md`
   - Chronological log of key actions, failures, retries, and decisions

4. `evaluation-summary.md`
   - Metric table, baseline deltas, regressions, and confidence notes

5. `decision.md`
   - Final `GO` or `NO-GO`
   - Blockers/risks and exact next commands

## Required JSON artifacts

Each sub-skill writes its own JSON artifact to `--out-dir`. See [../../../references/schemas.md](../../../references/schemas.md) for the full schema definitions and [../../../references/vocabulary.md](../../../references/vocabulary.md) for canonical enum values.

The `run_id` field in every artifact must match the one generated by `orchestrate-e2e` at run start.

## Generated artifacts

`report.html` is generated by `generate_report.py` after all gates complete:

```bash
uv run "${CLAUDE_SKILL_DIR}/scripts/generate_report.py" <out-dir>
```

## Quality bar

- Use absolute file paths for artifact references.
- Every headline number and every `blocker`/`high` finding has an `exec` block in `evidence.md`; the notebook verifies before promotion.
- Include at least one reproducible command per failed gate.
- Keep decision rationale concise and evidence-backed.
- All JSON artifacts must include `schema_version: "1.1"`, `run_id`, and `level`.
- Artifacts from skills that touch data or code must include `provenance`.
